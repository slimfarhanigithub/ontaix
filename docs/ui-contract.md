# Ontaix Studio — UI contract

The file `reference/ontaix-studio-reference.html` is the contract. It was built and approved
screen by screen with the owner; every rule below was a decision taken while building it.

## Acceptance
- Playwright screenshot suite: each scene below is rendered from the reference file and from the
  Studio at 1440×900 and 1920×1080, dark and light, and compared with a 0.1 % pixel tolerance.
- The scripted story is not part of the product (decision row 62). The reference file still contains it and is never edited; the harness injects one stylesheet into both the reference page and the Studio page that hides the story-only elements listed below, so the Studio is compared against the reference without them.
- Hidden in both pages by the injected stylesheet, with `display: none` so the surrounding layout closes up as it does in a Studio that never renders them: `#sceneNum` (the `Scene n of 14` counter, statically `Scene 0 of 15`) and `#sceneName` (the scene name) inside the header's `.scene` block, whose admin button `#adminOpen` stays visible; `#next` (the Next button with `#nextLabel`, for example `Next · Supply chain`); `#finalise` (the Finalise all tool button).
- `.hint` is compared pixel by pixel. Only its two story fragments go: a script the harness injects into both pages removes the first `kbd` (`Space`) and the whole text node after it (` next`, a space, a no-break space, a space), removes the last `kbd` (`R`) and the whole text node after it (` restart`), and replaces the text node after `<kbd>F</kbd>` with exactly ` full screen` (the reference's ` full screen `, a space, a no-break space and a space, carry the separator before `R`, and a no-break space does not collapse). The Studio renders the hint markup already in that form, so the script changes nothing there. Before the screenshot the harness asserts that `.hint` `textContent` is equal in both pages.
- Teach-bar placeholder: when `#say` is empty the Studio shows the reference's own non-story placeholder `Teach <company name>…` for the company being taught, with any number of companies, and `Live teaching is disabled in the admin portal` when live teaching is off, as the reference does. The reference shows `Teach <company name>…` only when it has two or more companies; with one company it shows the story text `Teach the model something, or press Next to follow the story`. The harness makes `#say::placeholder` transparent in both pages in scenes with one company and live teaching on. The teach bar itself is not compared against the reference (next item), so the placeholder is checked by the Studio-only teach bar baselines.
- The teach bar differs from the reference on purpose (decision row 134, spec under "Teach bar" below): the Studio's caption lives inside `form.bar`. Just before every reference-parity screenshot the harness injects `.caption,form.bar{visibility:hidden!important}` into both pages, so the reference's separate caption and bar and the Studio's compact bar are left out of the comparison; `visibility` keeps the Studio bar's 42 px height, which places `.tools` at the reference's `bottom:86px`, and every other pixel still compares at the usual tolerance. The harness clears `ontaix.teachBar.expanded` before loading the Studio, so every run starts collapsed. The bar has its own Studio-only baselines, `tests/screenshots/teachbar.spec.ts`, stored per platform under `tests/screenshots/baselines/` and compared at 0.1 %: collapsed idle, collapsed long caption, listening, processing, not understood, expanded and live teaching off, each at 1440×900 and 1920×1080 in dark and light and at 390×844 in dark and light. The Studio's caption holds an empty kicker and empty text until its first teach, import or decision, so no opening copy ships; the reference's opening caption stays hidden until then as before.
- Sign-in and platform screens exist only in the Studio, on purpose (decision row 140, ADR 0017 section 9): the sign-in page, the `Choose a new password` page, the `Change password` dialog, `#adminAccount` in the admin head (the signed-in email, `Change password`, `Sign out`, and `End support` during a support session), the platform portal (`Ontaix platform`: `Organizations`, `Platform audit log`) and the header `.status` pill `Support · <organization> · read-only`. They are built only from the reference's own classes and tokens (`--bg`, `.wordmark`, `.dlg.sm`, `.dh`, `.db`, `.df`, `.form`, `.msg`, `.btn.primary`, `.spin`, `.admin .win`, the list pattern) and add no token. The reference has no session, so it never renders `#adminAccount`; just before every reference-parity screenshot the harness injects `#adminAccount{visibility:hidden!important}` into both pages, and the Studio renders it only with a live session, which the in-browser mock never has. The sign-in page, the password page and the platform portal's two pages have their own Studio-only baselines, `tests/screenshots/auth.spec.ts`, stored per platform under `tests/screenshots/baselines/` and compared at 0.1 %: each at 1440×900 and 1920×1080 in dark and light, driven through Playwright routes that answer `GET /auth/session` and the platform routes with fixtures.
- The harness never plays a scene. It drives the reference through the paths the product keeps: sentences go through the reference's import path (`teach(sentence, true)`), which skips story interception; companies through the add-company dialog; sources and bindings through the data-source wizard; relations and cross-company equivalences through the relationship dialog (drop across companies, action `equivalent to`); decisions through the changes panel, Approve all and Reject all. It drives the Studio through the same user actions against the API, starting from the dev and test fixture's home company, Northwind Industries. Both reach the same state with the same seed and clock.
- Scenes: empty canvas (home company root only); a company added with its starter vocabulary pending; full fixture model - Northwind Industries taught through text and document import, Aurora Valves added with its starter vocabulary, sources bound through the wizard, equivalences proposed through the relationship dialog, everything approved with Approve all; pending proposals visible; approve / reject; domain focus; cell focus; lineage drawer; Arrange in each mode (full, domain, cell, lineage); Coverage view; every admin page; data-source wizard steps 1–3; relationship dialog; type-"disable" confirmation; two companies with equivalences; legend shown and hidden.
- The cell-division animation is compared frame-by-frame at 6 sampled frames.
- Waiting for teach extraction (up to 15 seconds for a typed or document sentence, 45 seconds for a speech transcript, decision row 91) shows the teach bar's `Processing` status (decision rows 132 and 134); waiting for concept expansion (up to 120 seconds by default, row 102) shows the spinners of row 132. Screenshot scenes are captured at rest, with neither.
- Voice teaching timing differs from the reference on purpose (decision row 127): each sentence the speech recogniser finishes is taught while the owner goes on speaking, so cells appear during speech rather than after the owner stops. Nothing else changes: the microphone button, its `on` state, the words shown in `#say` while listening, the placeholders, captions, toasts and cell-division animations are the reference's. Screenshot scenes include no speech.
- Refusal toasts differ from the reference on purpose (decision row 86). When the API refuses an action, the toast keeps the bold lead `Refused` and its body text is the Problem's `detail` (its `title` when `detail` is absent), rendered as text, for example `Refused Only a Governor or Owner can approve`. The reference has no server, so it has no refusal reasons. Only that body text differs; the toast's position, style, animation and 3-second life are the reference's. Screenshot scenes include no refusal toast.
- Deleting a concept differs from the reference on purpose (decision row 98). The cell drawer has a third action, `Delete` (`#drDelete`), after `Grow a concept from it` and `Lineage`, in the same `.drawer .actions button` style; it shows only for approved, live, non-root concepts and opens the same confirmation as Admin portal → Entities → Delete. That confirmation, from both entry points, reads `Delete <label>?` with the body `Its <n> descendants (<names>) and <m> relations go with it. This proposes a change for approval.` (singular forms for one; at most 6 names, then `and <k> more`; `Its <m> relations go with it. This proposes a change for approval.` when nothing descends from it), names rendered as text. Screenshot scenes: the injected stylesheet hides `#drDelete` in both pages with `display: none` (the reference has no such element), so every drawer and lineage scene compares the rest of the drawer against the reference at the usual tolerance; the Entities page scene is unaffected, and no scene shows the delete confirmation.
- Expanding a concept differs from the reference on purpose (decision rows 99, 103 and 105; ADR 0009). The cell drawer has `Expand` (`#drExpand`) immediately before `Delete`, in the same `.drawer .actions button` style, shown for approved live concepts and the company root, never for a pending cell or a source. It opens the reference's own `dialog()`: title `Expand <label>`, sub `The model suggests concepts to grow from it; each one is a proposal`, body a `.form` with `Depth` (a `select`: `Any depth` (default), `1`, `2`, `3`, `4`, `5`) and `Focus (optional)` (an `input`, at most 200 characters, placeholder `e.g. after-sales services`), primary button `Suggest`. Waiting adds no UI, as for teach extraction. When drafts arrive the same dialog's sub reads `<n> suggestions · <k> skipped` and its body lists one `.chk` row per draft, checkbox checked, in draft order: `<b>` the label (a relation: `<from> <action> <to>`) and `<small>` `level <depth> · <action> <parent label> · <confidence>% · <rationale>` (a relation: `<small>` `relation · <confidence>% · <rationale>`, decision row 126); unchecking a row unchecks every row that requires it, checking a row checks every row it requires; the primary button reads `Propose <n>` with the checked count and is disabled at 0. When the answer holds no draft the dialog closes and the reference's toast shows the bold lead `No suggestions` with the body `The model is not available` (`not_configured`, `provider_error`, `invalid_output`, `timeout`), `The model budget is spent` (`rate_limited`, `budget_exhausted`), `The model declined this request` (`refused`) or `Everything suggested is already in the model` (`used` with every suggestion skipped). All model text is rendered as text. Proposals with origin `suggestion` use the panel's existing markup only: the `.prop .top` text is the server's heading ending with ` · suggested` (for example `New concept · Sales · suggested`), and the `.prop .why` line holds the server's `why`, `Suggested by the model · <confidence>% · <rationale>`, as text. Screenshot scenes: the injected stylesheet hides `#drExpand` in both pages with `display: none`; no scene shows the Expand dialog or a suggested proposal; no tolerance changes.
- Whole-document extraction and branch approval differ from the reference on purpose (decision rows 106 and 109; ADR 0010). The Import button and the `I` key open the file picker directly, as in the reference (decision row 126); one `.tools` pill button, `#imMode`, in the tool row immediately after Import, in the style and `aria-pressed` pattern of Coverage and Skip: its label is the current mode, `Sentences` (default, the reference's path, `aria-pressed` false), `Whole document` or `Ontology` (`aria-pressed` true), each click moves to the next in that order and back to `Sentences`, and the picked or dropped file is read in the current mode; the pill is hidden with Import when `importDocs` is off. While a job runs, the existing `.caption` shows the kicker `Reading <file name>` and the text `Outline <i> of <n> · sections <j> of <n>`; when it ends, `<d> proposals from <file name>` (or `Nothing to propose from <file name>`, and on failure `Whole-document reading is not available` before falling back to sentence by sentence). In the changes panel, a ready `concept` or `spec` proposal whose `openBelow` is above 0 gets a third button in its `.prop .act` row, after `Reject`, in the same `.prop .act button` style: `Approve branch (<n>)`, where n is `openBelow` plus one; a response with `complete` false is followed by another call on the same root until it is complete or nothing more is ready; `Reject` keeps the reference's cascade, which already rejects the branch. The `Ontology` mode of `#imMode` (decision rows 115 and 126, ADR 0012) sends the file to ontology import with the browser's language list, individuals skipped and the taught company's root as parent; the `.caption` shows the kicker `Mapping <file name>`, then `<d> proposals from <file name> · <k> skipped`, and the tree is reviewed with `Approve branch` and the cascading reject. The file picker accepts every import type of ADR 0011 (PPTX, XLSX, HTML and scanned PDF included) and the ontology formats. Screenshot scenes: `#imMode` is shown, never hidden; the harness adds the same pill at its default to the reference after `#importFile`, shown or hidden with its Import button, so every other pixel still compares against the reference; no scene runs a job or an ontology import, so no scene shows the progress caption, and the injected stylesheet hides the `Approve branch` button (`.prop .act .branch`) in both pages with `display: none`; no tolerance changes.

- Taught attributes (decision row 130) use the drawer's existing `.drawer .attr` row: the name in `<b>`, the value as text in the `.col` line where a source attribute shows its column path, no `.fill` bar, and the existing `.state` pill. No screenshot scene contains a taught attribute. The pill keeps the reference's wording on purpose: a proposed taught attribute reads `found in data · pending` like a discovered one, and an approved one `approved`; the drawer adds no wording of its own.

## Do-not rules (each one was explicitly rejected by the owner)
- No glows, halos, particles, light bridges, shadow ghosts, dotted rims, or orbit lines. Cells are
  plain matte spheres with nothing around or inside them; a green rim after approval, a red fade
  after rejection, nothing else.
- No gamification: no levels, XP, trophies, bonuses, unlocks.
- No explosion or flash on division. A cell divides through a metaball neck with throb, mutual
  push, cleavage furrow and recoil; the child visibly comes out of the parent.
- No stripe across a newborn cell, no line inside a cell during colour changes.
- No `prompt()` / `alert()` / `confirm()`. Dialogs only, closed with an × button — no Cancel buttons.
- No verb chips in the relationship dialog; a text box with propose-change, suggest and
  reverse-direction icons.
- Enable/Disable toggles are fixed-width and aligned; never "Show/Hide" wording in the admin portal.
- Domain colour is identical for every cell in the domain and the same across companies; no
  brighter nuance inside a cluster.
- Company hull is fully filled, not a ring.
- No dependency on Microsoft for groups: native Ontaix groups.

## Behaviours that must be reproduced exactly
- Proposal contract: propose → pending (drawn lighter, "awaiting approval") → approve (green rim,
  domain version +1) / reject (red fade, cascade to descendants); two-approver option; audit log;
  Approve all / Reject all; Skip animation.
- Cells are born only by division from a parent; lineage (parent, birth link, born-at) is persisted.
- Teach: rule-based parser first (subject → action → object, "is a", "In <domain>, …", lists,
  passives); anything unresolved becomes a proposed new cell, never a silent creation.
- Suggest action: subject's own actions first, then DOES by subject, then DONE_TO by object.
- Focus: hover shows the neighbourhood; click is sticky focus; domain click focuses the domain
  using the nearest-cell rule; Arrange acts on the highlighted set only and stages it in a clear
  area to the right of everything else, then fits.
- Coverage view fades unbound cells; sources are brass rounded squares anchored outside the
  domain ring; bindings carry record counts and freshness; discovered attributes are proposed.
- Admin portal pages, in this order: Overview, Tenant settings, Appearance, Data sources,
  Connectors, Entities, Relationships, Bindings, Companies, Domain products, Groups, Users,
  Roles, Audit log, Cost management. Lists are searchable, filterable, sortable, paginated
  (thousands of agents expected). Adding a company from the portal keeps the portal open.
- "Companies may interact" switch: disabling it when links exist requires typing `disable`
  and removes every cross-company link.
- Theme switch (dark/light) in the admin header and Appearance; colour pickers per domain.
- Keyboard: P panel, D domains card, L legend, G admin, A arrange, I import, C coverage, S skip animation, F full screen, Escape; no Space, ArrowRight or R (story shortcuts, removed by decision row 62). A letter does nothing while the focus is in an `input`, `select`, `textarea` or editable content, while Ctrl, Alt or Meta is held, or while a dialog is open; with the admin portal open only G (close it) works. Escape closes the top dialog wherever the focus is, and neither the canvas nor the admin portal reacts to that Escape (decision row 134).
- Dialogs (every `.dlg`) and the admin portal are named by their title through `aria-labelledby` (the portal by `#adminTitle`, `Ontaix admin portal`), keep Tab and Shift+Tab inside themselves, and give focus back to the element that had it when they close. When a dialog's focused button waits (decision row 132), the focus moves to the `.dlg` frame (`tabindex="-1"`, no outline), so Escape still closes it (decision row 134).
- `Reject all` and a cascading `Reject` ask first in the reference's `confirmDialog` (`Cancel` and a `danger` button), as neither can be undone (decision row 134): `Reject all` opens `Reject <n> proposals?` (`Reject 1 proposal?`) with the body `Every pending proposal is discarded. This cannot be undone.` and the button `Reject all`; `Reject` on a proposal whose `openBelow` is above 0 opens `Reject <label> and the <n> proposals below it?` (`and the proposal below it?` for one) with the body `Every proposal that grows from it is rejected with it. This cannot be undone.` and the button `Reject`. `Reject` with nothing below rejects at once. The caption after the decision is unchanged.
- Content enters as speech (teach bar microphone, transcribed to text), text (teach bar), documents (import, extracted by the API, sentence by sentence or as a whole) or ontology files (import, mapped by the API); each becomes proposals.
- Everything persists (state survives reload and full-screen).
- An awaited click shows `.spin` before the label after 250 ms, and the button is disabled until it settles (decision row 132). On the `.tg` toggle and the Import tool button the spinner takes the dot's or icon's place. While Expand suggestions load, the dialog body reads `<span class="spin"></span>Expanding <b>{concept}</b>…` and the drawer's Expand button spins.
- While a teach bar parse is pending (typed, spoken or imported), the teach bar's status slot `#teachStatus` reads `<span class="spin"></span>Processing` after 250 ms, `Processing · <n> queued` while more parses wait behind the first, and stays at least 400 ms once shown, until the parses settle; typing and listening stay available (decision rows 132 and 134).

## Teach bar
Decision row 134. Every value is a reference token, size, radius, weight or keyframe; the rules live in `apps/studio/src/styles/studio.css`.

- Collapsed: `form.bar` is one pill 42 px high (padding `4px 4px 4px 6px`, gap 6 px, 1 px `var(--line)` border, radius 999 px, `var(--panel)`, `blur(14px)`), at the reference's width and `bottom:30px`. Children, in order: the disclosure button `#teachMore`, a 1 × 18 px `var(--line)` divider, `#companySel` (two or more companies only), `#say`, the status slot `#teachStatus`, `#mic` (32 × 32) and `#teach` (`Teach`, padding `0 12px`). Buttons and the select are 32 px high with 12.5 px text; `#say` is 14 px and ends with an ellipsis when it has no focus.
- `#teachMore` (`type="button"`, `aria-expanded`, `aria-controls="teachLog"`, `title` the full caption): a 14 px chevron (the `.tools` icon stroke), the kicker `#captionKicker` (12 px, weight 500, `var(--ink-3)`) and the text `#captionText` (12.5 px, weight 300, `var(--ink-2)`, one line, ellipsis), typed 16 ms per character (4 ms with reduced motion). It shows the newest history entry; empty until the first teach, import, decision or refusal.
- History: the last 5 captions, newest last; a caption identical to the newest is not added again; each refusal toast (`Refused <reason>`) is copied in. It lives for the session only.
- The `.tools` row sits at `bottom: calc(var(--teach-h) + 44px)`, where `--teach-h` is the bar's measured height: 86 px collapsed, as in the reference.
- Expanded: the same element grows upward into a card (radius 16 px, padding `10px 4px 4px 6px`). On top, `#teachLog` (`role="log"`, `aria-label="Recent captions"`, `tabindex="0"`, `max-height:min(40vh,320px)`, scrolls, opens with `fade .15s`): the title `Recent` in the `.drawer h3` style, then one row per entry (kicker 12 px weight 500 `var(--ink)`, text 13 px `var(--ink-2)` line height 1.5, `border-top:1px solid var(--line)`, `padding:6px 0`, entering with `propin .3s`), scrolled to the newest. Below it `#say` is a `textarea` of 1 to 5 lines (14 px, line height 1.5) that then scrolls, read-only while listening. The bottom row holds the button, now showing the chevron turned 180 degrees and `Hide`, then the company select, the status, the microphone and Teach.
- States of the button and the status: idle, the newest caption; listening, the 7 px `var(--conflict)` dot, `Listening` and the last sentence the recogniser finished, status empty; processing, the caption unchanged and the status `.spin` + `Processing` (min width 92 px, `fade .15s`); not understood or refused, the kicker in `var(--conflict)`; a new caption cut short while collapsed turns the chevron `var(--accent)` for 2 s; live teaching off, `#say` disabled with its contract placeholder.
- Keys: Enter or Space on `#teachMore` toggles it; Enter in `#say` teaches; Shift+Enter in the text area starts a new line; Escape anywhere in the open bar closes it, gives focus back to `#teachMore` and goes no further (the canvas does not release its focus). Tab order: `#teachMore`, `#companySel`, `#say`, `#mic`, `#teach`, then `#teachLog` when open. Every control has the `2px solid var(--accent)` focus ring with a 2 px offset.
- Remembered: `localStorage` key `ontaix.teachBar.expanded` (`1` open, `0` closed), read and written inside `try`/`catch`; collapsed when nothing can be read.
- A typed sentence stays in `#say` while it is parsed and is sent once; it clears once taught (understood or partly understood, its proposals accepted). When it is not understood, or the parse or its proposals are refused, it is put back in `#say` and selected, unless a newer sentence is already there.
- Under 900 px: the card (radius 16 px, row gap 4 px) has two rows, `#teachMore` alone on the first (24 px high) and the controls on the second, 70 px in all; the divider is hidden and the status keeps its spinner while `Processing` stays readable to screen readers only. Open, the history's `max-height` is `55vh`.

## Porting rule
The canvas renderer (cells, division, hulls, links, labels, arrange, focus, lineage) is ported
from the reference **verbatim** into TypeScript modules. Refactoring for structure is allowed;
changing a constant, an easing, a colour or a threshold is not.
