# Ontaix Studio — UI contract

The file `reference/ontaix-studio-reference.html` is the contract. It was built and approved
screen by screen with the owner; every rule below was a decision taken while building it.

## Acceptance
- Playwright screenshot suite: each scene below is rendered from the reference file and from the
  Studio at 1440×900 and 1920×1080, dark and light, and compared with a 0.1 % pixel tolerance.
- The scripted story is not part of the product (decision row 62). The reference file still contains it and is never edited; the harness injects one stylesheet into both the reference page and the Studio page that hides the story-only elements listed below, so the Studio is compared against the reference without them.
- Hidden in both pages by the injected stylesheet, with `display: none` so the surrounding layout closes up as it does in a Studio that never renders them: `#sceneNum` (the `Scene n of 14` counter, statically `Scene 0 of 15`) and `#sceneName` (the scene name) inside the header's `.scene` block, whose admin button `#adminOpen` stays visible; `#next` (the Next button with `#nextLabel`, for example `Next · Supply chain`); `#finalise` (the Finalise all tool button).
- `.hint`, the legend `#legend` and its toggle `#legendToggle` are the Studio's own (decision row 153, "Canvas docks" below): the Studio draws them with its own icons, labels, text and placement, so they have no counterpart in the reference. Just before every reference-parity screenshot the harness hides them in both pages with `visibility: hidden`, together with the teach bar (next item), and the Studio-only teach bar baselines, whose bottom strip holds them, cover them. The harness does not compare the `.hint` text; the Studio's shortcuts are listed under "Canvas docks".
- Teach-bar placeholder: when `#say` is empty the Studio shows the reference's own non-story placeholder `Teach <company name>…` for the company being taught, with any number of companies, and `Live teaching is disabled in the admin portal` when live teaching is off, as the reference does. The reference shows `Teach <company name>…` only when it has two or more companies; with one company it shows the story text `Teach the model something, or press Next to follow the story`. The harness makes `#say::placeholder` transparent in both pages in scenes with one company and live teaching on. The teach bar itself is not compared against the reference (next item), so the placeholder is checked by the Studio-only teach bar baselines.
- The teach bar differs from the reference on purpose (decision row 134, spec under "Teach bar" below): the Studio's caption lives inside `form.bar`. Just before every reference-parity screenshot the harness injects `.caption,form.bar,.legend,#legendToggle,.hint{visibility:hidden!important}` into both pages, so the reference's separate caption and bar and the Studio's compact bar, legend and shortcuts are left out of the comparison; `visibility` keeps the Studio bar's 42 px height, which places `.tools` at the reference's `bottom:86px`, and every other pixel still compares at the usual tolerance. The harness clears `ontaix.teachBar.expanded` before loading the Studio, so every run starts collapsed. The bar has its own Studio-only baselines, `tests/screenshots/teachbar.spec.ts`, stored per platform under `tests/screenshots/baselines/` and compared at 0.1 %: collapsed idle, collapsed long caption, listening, processing, not understood, expanded and live teaching off, each at 1440×900 and 1920×1080 in dark and light and at 390×844 in dark and light. The Studio's caption holds an empty kicker and empty text until its first teach, import or decision, so no opening copy ships; the reference's opening caption stays hidden until then as before.
- Sign-in and platform screens exist only in the Studio, on purpose (decision row 140, ADR 0017 section 9): the sign-in page, the `Choose a new password` page, the `Change password` dialog, `#adminAccount` in the admin head (the signed-in email, `Change password`, `Sign out`, and `End support` during a support session), the platform portal (`Ontaix platform`: `Organizations`, `Platform audit log`) and the header `.status` pill `Support · <organization> · read-only`. They are built only from the reference's own classes and tokens (`--bg`, `.wordmark`, `.dlg.sm`, `.dh`, `.db`, `.df`, `.form`, `.msg`, `.btn.primary`, `.spin`, `.admin .win`, the list pattern) and add no token. The reference has no session, so it never renders `#adminAccount`; just before every reference-parity screenshot the harness injects `#adminAccount{visibility:hidden!important}` into both pages, and the Studio renders it only with a live session, which the in-browser mock never has. The sign-in page, the password page and the platform portal's two pages have their own Studio-only baselines, `tests/screenshots/auth.spec.ts`, stored per platform under `tests/screenshots/baselines/` and compared at 0.1 %: each at 1440×900 and 1920×1080 in dark and light, driven through Playwright routes that answer `GET /auth/session` and the platform routes with fixtures, in a browser context pinned to UTC so the audit log's times read the same on every machine, and captured once the window's or dialog's entrance animation has ended on its own (`animationsSettled` in `tests/screenshots/harness.ts`), so no capture holds a mid-way frame.
- Skip animation is a setting on the admin portal's Appearance page, not a tool button (decision row 153). The harness hides the reference's `#skip` in both pages with `display: none`, so the reference's tool row closes up as the Studio's does, and both pages skip animations with the `S` key. The harness adds the Studio's `apps/studio/src/styles/admin-rows.css` to both pages (the Studio already loads it), and, each time the reference renders an admin page and before its layout, gives it what the Studio adds, from `apps/studio/src/admin/rowText.ts`: the description of each setting row the reference leaves empty and, on Appearance, the `Motion` heading and the `Skip animation` row after the Theme row, its toggle showing the reference's own skip state. Every other pixel of every admin scene still compares at the usual tolerance.
- The harness never plays a scene. It drives the reference through the paths the product keeps: sentences go through the reference's import path (`teach(sentence, true)`), which skips story interception; companies through the add-company dialog; sources and bindings through the data-source wizard; relations and cross-company equivalences through the relationship dialog (drop across companies, action `equivalent to`); decisions through the changes panel, Approve all and Reject all. It drives the Studio through the same user actions against the API, starting from the dev and test fixture's home company, Northwind Industries. Both reach the same state with the same seed and clock.
- Scenes: empty canvas (home company root only); a company added with its starter vocabulary pending; full fixture model - Northwind Industries taught through text and document import, Aurora Valves added with its starter vocabulary, sources bound through the wizard, equivalences proposed through the relationship dialog, everything approved with Approve all; pending proposals visible; approve / reject; domain focus; cell focus; lineage drawer; Arrange in each mode (full, domain, cell, lineage); Coverage view; every admin page; data-source wizard steps 1–3; relationship dialog; type-"disable" confirmation; two companies with equivalences; legend shown and hidden.
- The cell-division animation is compared frame-by-frame at 6 sampled frames.
- Waiting for teach extraction (up to 15 seconds for a typed or document sentence, 45 seconds for a speech transcript, decision row 91) shows the teach bar's `Processing` status (decision rows 132 and 134); waiting for concept expansion (up to 120 seconds by default, row 102) shows the spinners of row 132. Screenshot scenes are captured at rest, with neither.
- Voice teaching timing differs from the reference on purpose (decision row 127): each sentence the speech recogniser finishes is taught while the owner goes on speaking, so cells appear during speech rather than after the owner stops. With Azure Speech, 500 ms of silence ends a sentence (`Speech_SegmentationSilenceTimeoutMs`, ADR 0013, decision row 135), so a finished sentence is taught sooner; this is timing only. Nothing else changes: the microphone button, its `on` state, the words shown in `#say` while listening, the placeholders, captions, toasts and cell-division animations are the reference's. Screenshot scenes include no speech.
- Refusal toasts differ from the reference on purpose (decision row 86). When the API refuses an action, the toast keeps the bold lead `Refused` and its body text is the Problem's `detail` (its `title` when `detail` is absent), rendered as text, for example `Refused Only a Governor or Owner can approve`. The reference has no server, so it has no refusal reasons. Only that body text differs; the toast's position, style, animation and 3-second life are the reference's. Screenshot scenes include no refusal toast.
- Deleting a concept differs from the reference on purpose (decision row 98). The cell drawer offers `Delete` (`#drDelete`) as the last item of its More actions menu ("Drawer More actions menu" under "Ontology Editing And Domains"), after a divider and in the reference's conflict red; it shows only for approved, live, non-root concepts and opens the same confirmation as Admin portal → Entities → Delete. That confirmation, from both entry points, reads `Delete <label>?` with the body `Its <n> descendants (<names>) and <m> relations go with it. This proposes a change for approval.` (singular forms for one; at most 6 names, then `and <k> more`; `Its <m> relations go with it. This proposes a change for approval.` when nothing descends from it), names rendered as text. Screenshot scenes: the injected stylesheet hides the More actions button (`[data-ox-new]`) in both pages with `display: none` (the reference has no such element) and the reference's two action buttons as "Drawer More actions menu" describes, and no scene opens its menu, so every drawer and lineage scene compares the rest of the drawer against the reference at the usual tolerance; the Entities page scene is unaffected, and no scene shows the delete confirmation.
- Expanding a concept differs from the reference on purpose (decision rows 99, 103 and 105; ADR 0009). The cell drawer has `Expand…` (`#drExpand`), the third item of its More actions menu, after `Grow a concept from it` and `Lineage` ("Drawer More actions menu" under "Ontology Editing And Domains"), shown for approved live concepts and the company root, never for a pending cell or a source. It opens the reference's own `dialog()`: title `Expand <label>`, sub `The model suggests concepts to grow from it; each one is a proposal`, body a `.form` with `Depth` (a `select`: `Any depth` (default), `1`, `2`, `3`, `4`, `5`) and `Focus (optional)` (an `input`, at most 200 characters, placeholder `e.g. after-sales services`), primary button `Suggest`. Waiting adds no UI, as for teach extraction. When drafts arrive the same dialog's sub reads `<n> suggestions · <k> skipped` and its body is a full-width list `.ex-list` (`role="group"`, `aria-label="Suggestions to grow from <label>"`, not inside `.form`, decision row 153): a header row `.ex-head` (`aria-hidden`, 11 px uppercase `var(--ink-3)`: an empty cell, `Suggestion`, `Link`, `Confidence`), then one `label.chk.ex-row` per draft, checkbox checked, in draft order, on the grid `16px minmax(0,1.3fr) minmax(0,1fr) 76px` with a 12 px column gap: the checkbox, `<b class="ex-label">` the label (a relation: `<from> <action> <to>`), `.ex-verb` `<action> <parent label>` (a relation: `relation`) in 12.5 px `var(--ink-2)`, `.ex-conf` `<confidence>%` right-aligned with tabular figures, and below them, from the label column to the end, `<small class="ex-note">` `level <depth> · <rationale>` (a relation: `<rationale>`) with line height 1.5; every text wraps (`overflow-wrap:anywhere`) and nothing is cut; rows are 6 px apart; under 600 px the header hides and the link moves under the label; unchecking a row unchecks every row that requires it, checking a row checks every row it requires; the primary button reads `Propose <n>` with the checked count and is disabled at 0. When the answer holds no draft the dialog closes and the reference's toast shows the bold lead `No suggestions` with the body `The model is not available` (`not_configured`, `provider_error`, `invalid_output`, `timeout`), `The model budget is spent` (`rate_limited`, `budget_exhausted`), `The model declined this request` (`refused`) or `Everything suggested is already in the model` (`used` with every suggestion skipped). All model text is rendered as text. Proposals with origin `suggestion` use the panel's existing markup only: the `.prop .top` text is the server's heading ending with ` · suggested` (for example `New concept · Sales · suggested`), and the `.prop .why` line holds the server's `why`, `Suggested by the model · <confidence>% · <rationale>`, as text. Screenshot scenes: the injected stylesheet hides the More actions button (`[data-ox-new]`) in both pages with `display: none` and no scene opens its menu; no scene shows the Expand dialog or a suggested proposal; no tolerance changes.
- Whole-document extraction and branch approval differ from the reference on purpose (decision rows 106 and 109; ADR 0010). The Import button and the `I` key open the file picker directly, as in the reference (decision row 126). What a picked or dropped file is, is detected, not chosen first (decision row 137): the file goes to `POST /import/detect`, the Import button showing its waiting state meanwhile; a document is read whole, with the detected media type, and an ontology goes to ontology import in the detected format. When detection refuses the file, the `.caption` shows the kicker `Import failed` and the text `<file name> could not be read (<reason>).`, reason as text. Once a file has been detected, one `.tools` pill button, `#imAs`, stands in the tool row immediately after Import, in the style of Coverage, with the lines icon (`M3 4h10M3 8h10M3 12h6`), no `aria-pressed`, the title `Read <file name> another way`, and the label `Read as: <reading>`, where the reading is one of `Document (whole)`, `Document (sentences)`, `Ontology (Turtle)`, `Ontology (RDF/XML)`, `Ontology (JSON-LD)`, `Ontology (OWL/XML)`, `Ontology (N-Triples)`, `Ontology (OBO)`, `Ontology (CSV)` or `Ontology (XLSX)`; it is disabled while an import runs and hidden with Import when `importDocs` is off, and there is no pill before the first import. A click opens the reference's small `dialog()` (as its Bind dialog): title `Read <file name> as`, body a `.form` with `grid-template-columns:90px 1fr` holding the label `Read as` and a `select` (`#imAsRead`) of the ten readings in that order, the current one selected, then an empty label and a `<small>` in `var(--ink-3)` reading `Detected as <detected reading>. The file is imported again, read the way chosen.`; buttons `Cancel` and the primary `Import again`, which closes the dialog and imports the same file read the chosen way (a document reading sends the detected media type, an ontology reading sends the chosen format), and the pill's label follows. While a job runs, the existing `.caption` shows the kicker `Reading <file name>` and the text `Outline <i> of <n> · sections <j> of <n>`; when it ends, `<d> proposals from <file name>` (or `Nothing to propose from <file name>`, and on failure `Whole-document reading is not available` before falling back to sentence by sentence). In the changes panel, a ready `concept` or `spec` proposal whose `openBelow` is above 0 gets a third button in its `.prop .act` row, after `Reject`, in the same `.prop .act button` style: `Approve branch (<n>)`, where n is `openBelow` plus one; a response with `complete` false is followed by another call on the same root until it is complete or nothing more is ready; `Reject` keeps the reference's cascade, which already rejects the branch. An ontology reading (decision rows 115, 126 and 135, ADR 0012) sends the file to ontology import in its format with the browser's language list, individuals skipped and the taught company's root as parent; the `.caption` shows the kicker `Mapping <file name>`, then `<d> proposals from <file name> · <k> skipped`, and the tree is reviewed with `Approve branch` and the cascading reject. The file picker accepts every import type of ADR 0011 (PPTX, XLSX, HTML and scanned PDF included) and the ontology formats. Screenshot scenes: `full-fixture-model` imports a file, so the injected stylesheet hides `#imAs` at capture as an owner addition (like `#drExpand`) and nothing is added to the reference; no scene runs a job or an ontology import, so no scene shows the progress caption, and the injected stylesheet hides the `Approve branch` button (`.prop .act .branch`) in both pages with `display: none`; no tolerance changes.

- Export differs from the reference on purpose (decision rows 148 and 149, ADR 0016). The admin portal's Companies page has a second button after `+ Add a company`, `Export` (`.btn`, `data-act="export"`, `data-ox-new`, 8 px to its left). It opens the reference's own `dialog()`: title `Export the ontology`, sub `the approved model as OWL, SKOS or a Word document`, body a `.form` with `Format` (a `select`: `OWL 2 · RDF/XML (.owl)` (default), `OWL 2 · OWL/XML (.owx)`, `OWL 2 · Turtle (.ttl)`, `OWL 2 · JSON-LD (.jsonld)`, `SKOS · Turtle (.skos.ttl)`, `Word document (.docx)`) and `Scope` (a `select`: `Everything I can read` (default), `One company`, `One domain product`); `One company` adds `Company` (a `select` of the companies, the one being taught first chosen), `One domain product` adds `Company` and `Domain product` (a `select` of that company's domain products holding a concept). The only footer button is the primary `Export`, closed with × as every dialog. The button waits as row 132 describes; the API's file is saved by the browser under the name its `Content-Disposition` gives, the dialog closes and the reference's toast shows the bold lead `Exported` with the file name. Screenshot scenes: the injected stylesheet hides every `[data-ox-new]` element in both pages with `display: none`, so the Companies page compares against the reference; no scene opens the Export dialog; no tolerance changes.

- Taught attributes (decision row 130) use the drawer's existing `.drawer .attr` row: the name in `<b>`, the value as text in the `.col` line where a source attribute shows its column path, no `.fill` bar, and the existing `.state` pill. No screenshot scene contains a taught attribute. The pill keeps the reference's wording on purpose: a proposed taught attribute reads `found in data · pending` like a discovered one, and an approved one `approved`; the drawer adds no wording of its own.

## Do-not rules (each one was explicitly rejected by the owner)
- No glows, halos, particles, light bridges, shadow ghosts, dotted rims, or orbit lines. Cells are
  plain matte spheres with nothing around or inside them; a green rim after approval, a red fade
  after rejection, nothing else.
- No gamification: no levels, XP, trophies, bonuses, unlocks.
- No explosion or flash on division. A cell divides through a metaball neck with throb, mutual
  push, cleavage furrow and recoil; the child visibly comes out of the parent.
- No stripe across a newborn cell, no line inside a cell during colour changes.
- No `prompt()` / `alert()` / `confirm()`. Dialogs only, closed with an × button — no Cancel buttons.
- No verb chips in the relationship dialog; a text box with propose-change, suggest and
  reverse-direction icons.
- Enable/Disable toggles are fixed-width and aligned; never "Show/Hide" wording in the admin portal.
- Domain colour is identical for every cell in the domain and the same across companies; no
  brighter nuance inside a cluster.
- Company hull is fully filled, not a ring.
- No dependency on Microsoft for groups: native Ontaix groups.

## Behaviours that must be reproduced exactly
- Proposal contract: propose → pending (drawn lighter, "awaiting approval") → approve (green rim,
  domain version +1) / reject (red fade, cascade to descendants); two-approver option; audit log;
  Approve all / Reject all; Skip animation (a setting on the admin portal's Appearance page and the `S` key, decision row 153).
- Cells are born only by division from a parent; lineage (parent, birth link, born-at) is persisted.
- Teach: rule-based parser first (subject → action → object, "is a", "In <domain>, …", lists,
  passives); anything unresolved becomes a proposed new cell, never a silent creation.
- Suggest action: subject's own actions first, then DOES by subject, then DONE_TO by object.
- Focus: hover shows the neighbourhood; click is sticky focus; domain click focuses the domain
  using the nearest-cell rule; Arrange acts on the highlighted set only and stages it in a clear
  area to the right of everything else, then fits.
- Arrange layout (decision row 163, a deliberate departure from the reference's spirals and rings): every arrangement is a layered tree read from left to right. Each tree level is a column; two neighbouring columns sit far enough apart for the widest labels of both and for every action chip between them; subtrees are packed one under another with 26 px between cells of a column and 64 px more where two domain products meet; a parent sits between its first and last child, so birth links never cross. Children keep their domain products together and are ordered to keep relations and equivalences from crossing (barycentre sweeps, then a bounded local search). A chip that would still cover a cell or another chip pushes its subtree down or widens its column; a labelled link between two cells of one column gets room for its chip. With nothing highlighted, each company's tree grows from its root to both sides (the root stays put) with every domain product in one region of its own: the cells of a domain product whose birth parent lies in another domain product all hang, for the layout, from one cell (the parent of the largest of them), so a domain product never splits; a parent sits between its children of its own domain product; children that carry another domain product go to the outside of their siblings; where a link passes from one domain product to another the two columns are 120 px further apart; two domain products in one column keep 150 px more than the label gap, and a domain product's top keeps that room from other domain products one column to each side, so neither the 86 px tints nor the headers meet. When a region still comes within 24 px of another region (or a header within 24 px of another region), the domain product that hangs from inside it moves to start one empty column after that region's last column, its link passing under the cells it skips, and the tree is laid out again (at most 3 times; once above 150 concepts). Sources sit beside the first concept bound to them, in its domain product's block (their anchor moves there); cells without a living parent hang from the root; two companies' trees keep at least 420 px apart. The camera fits the model as before; when that fit would be below 0.55 (the renderer draws chips above 0.5 and cell labels above 0.45), the camera stays at 0.55, centred on the active company, and the rest is a pan away. Lineage: the oldest non-root ancestor on the left, the cell, then its descendants to the right. Cell: the cell in the middle, what points to it on the left, what it points to on the right, grouped by domain product. Domain: the domain's members as their own trees from one column, each related cell of another domain beside the member it touches. Staged sets start 560 px right of the rightmost other cell, centred on the others' vertical middle. Captions: `Lineage of <Cell>, arranged` · `Moved to a clear area: ancestors on the left, descendants to the right, siblings one under another. The rest of the model is untouched and out of the way.`; `<Domain>, arranged` · `Moved to a clear area: N concepts of <Domain> from left to right, the M concepts it relates to beside what they touch. Press Arrange with nothing selected to put everything back.`; `<Cell> and its relations, arranged` · `Moved to a clear area: <Cell> in the middle, its N linked concepts around it, what points to it on the left and what it points to on the right, grouped by domain product. Press Arrange with nothing selected to put everything back.` Room is measured with the canvas's own text widths (`measureText` in the Sora fonts the renderer uses). No screenshot scene runs Arrange.
- Coverage view fades unbound cells; sources are brass rounded squares anchored outside the
  domain ring; bindings carry record counts and freshness; discovered attributes are proposed.
- Admin portal pages, in this order: Overview, Tenant settings, Appearance, Data sources,
  Connectors, Entities, Relationships, Bindings, Companies, Domain products, Groups, Users,
  Roles, Audit log, Cost management. Lists are searchable, filterable, sortable, paginated
  (thousands of agents expected). Adding a company from the portal keeps the portal open.
- "Companies may interact" switch: disabling it when links exist requires typing `disable`
  and removes every cross-company link.
- Theme switch (dark/light) in the admin header and Appearance; colour pickers per domain.
- Keyboard: P panel, D domains card, L legend, G admin, A arrange, I import, C coverage, S skip animation (the user's Skip animation setting, decision row 153), F full screen, Escape; no Space, ArrowRight or R (story shortcuts, removed by decision row 62). A letter does nothing while the focus is in an `input`, `select`, `textarea` or editable content, while Ctrl, Alt or Meta is held, or while a dialog is open; with the admin portal open only G (close it) works. Escape closes the top dialog wherever the focus is, and neither the canvas nor the admin portal reacts to that Escape (decision row 134).
- Dialogs (every `.dlg`) and the admin portal are named by their title through `aria-labelledby` (the portal by `#adminTitle`, `Ontaix admin portal`), keep Tab and Shift+Tab inside themselves, and give focus back to the element that had it when they close. When a dialog's focused button waits (decision row 132), the focus moves to the `.dlg` frame (`tabindex="-1"`, no outline), so Escape still closes it (decision row 134).
- `Reject all` and a cascading `Reject` ask first in the reference's `confirmDialog` (`Cancel` and a `danger` button), as neither can be undone (decision row 134): `Reject all` opens `Reject <n> proposals?` (`Reject 1 proposal?`) with the body `Every pending proposal is discarded. This cannot be undone.` and the button `Reject all`; `Reject` on a proposal whose `openBelow` is above 0 opens `Reject <label> and the <n> proposals below it?` (`and the proposal below it?` for one) with the body `Every proposal that grows from it is rejected with it. This cannot be undone.` and the button `Reject`. `Reject` with nothing below rejects at once. The caption after the decision is unchanged.
- Content enters as speech (teach bar microphone, transcribed to text), text (teach bar), documents (import, extracted by the API, sentence by sentence or as a whole) or ontology files (import, mapped by the API); each becomes proposals.
- Everything persists (state survives reload and full-screen).
- An awaited click shows `.spin` before the label after 250 ms, and the button is disabled until it settles (decision row 132). On the `.tg` toggle and the Import tool button the spinner takes the dot's or icon's place. While Expand suggestions load, the dialog body reads `<span class="spin"></span>Expanding <b>{concept}</b>…` and the drawer's Expand button spins.
- While a teach bar parse is pending (typed, spoken or imported), the teach bar's status slot `#teachStatus` reads `<span class="spin"></span>Processing` after 250 ms, `Processing · <n> queued` while more parses wait behind the first, and stays at least 400 ms once shown, until the parses settle; typing and listening stay available (decision rows 132 and 134).

## Teach bar
Decision row 134. Every value is a reference token, size, radius, weight or keyframe; the rules live in `apps/studio/src/styles/studio.css`.

- Collapsed: `form.bar` is one pill 42 px high (padding `4px 4px 4px 6px`, gap 6 px, 1 px `var(--line)` border, radius 999 px, `var(--panel)`, `blur(14px)`), at the reference's width (capped by the canvas docks, below) and `bottom:30px`. Children, in order: the disclosure button `#teachMore`, a 1 × 18 px `var(--line)` divider, `#companySel` (two or more companies only), `#say`, the status slot `#teachStatus`, `#mic` (32 × 32) and `#teach` (`Teach`, padding `0 12px`). Buttons and the select are 32 px high with 12.5 px text; `#say` is 14 px and ends with an ellipsis when it has no focus.
- `#teachMore` (`type="button"`, `aria-expanded`, `aria-controls="teachLog"`, `title` the full caption, `flex:0 1 auto`, at most `min(280px,45%)` of the bar, decision row 153): a 14 px chevron (the `.tools` icon stroke), the kicker `#captionKicker` (12 px, weight 500, `var(--ink-3)`) and the text `#captionText` (12.5 px, weight 300, `var(--ink-2)`, one line, ellipsis), typed 16 ms per character (4 ms with reduced motion). It shows the newest history entry; empty until the first teach, import, decision or refusal.
- History: the last 5 captions, newest last; a caption identical to the newest is not added again; each refusal toast (`Refused <reason>`) is copied in. It lives for the session only.
- The `.tools` row sits at `bottom: calc(var(--teach-h) + 44px)`, where `--teach-h` is the bar's measured height: 86 px collapsed, as in the reference.
- Expanded: the same element grows upward into a card (radius 16 px, padding `10px 4px 4px 6px`). On top, `#teachLog` (`role="log"`, `aria-label="Recent captions"`, `tabindex="0"`, `max-height:min(40vh,320px)`, scrolls, opens with `fade .15s`): the title `Recent` in the `.drawer h3` style, then one row per entry (kicker 12 px weight 500 `var(--ink)`, text 13 px `var(--ink-2)` line height 1.5, `border-top:1px solid var(--line)`, `padding:6px 0`, entering with `propin .3s`), scrolled to the newest. Below it `#say` is a `textarea` of 1 to 5 lines (14 px, line height 1.5) that then scrolls, read-only while listening. The bottom row holds the button, now showing the chevron turned 180 degrees and `Hide`, then the company select, the status, the microphone and Teach.
- States of the button and the status: idle, the newest caption; listening, the 7 px `var(--conflict)` dot, `Listening` and the last sentence the recogniser finished, status empty; processing, the caption unchanged and the status `.spin` + `Processing` (min width 92 px, `fade .15s`); not understood or refused, the kicker in `var(--conflict)`; a new caption cut short while collapsed turns the chevron `var(--accent)` for 2 s; live teaching off, `#say` disabled with its contract placeholder.

## Porting rule
The canvas renderer (cells, division, hulls, links, labels, arrange, focus, lineage) is ported
from the reference **verbatim** into TypeScript modules. Refactoring for structure is allowed;
changing a constant, an easing, a colour or a threshold is not. Exception: the Arrange layout (decision row 163) replaces the reference's placement; `fitTo`, the tween, `stageOrigin` and every drawing routine stay verbatim.
